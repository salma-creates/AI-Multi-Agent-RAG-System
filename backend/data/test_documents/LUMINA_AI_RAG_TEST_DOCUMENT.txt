1. INTRODUCTION

Lumina AI is an AI-powered knowledge retrieval system designed to answer questions using information available in a user's knowledge base.

This document is created specifically to test document ingestion, chunking, semantic retrieval, response generation, source attribution, confidence handling, and hallucination prevention.


2. UNIQUE TEST FACTS

The Lumina RAG test project was created in the year 2026.

The unique project code for this document is LUMINA-8472.

The retrieval similarity threshold used in this test is 0.73.

The maximum number of retrieved chunks in the standard test configuration is 5.

The minimum number of retrieved chunks in the basic test configuration is 1.

The Lumina test environment contains exactly 5 AI agents.


3. AI AGENTS

The five AI agents used in the Lumina test environment are:

1. Query Understanding Agent
2. Retrieval Agent
3. Response Generation Agent
4. Clarification Agent
5. Conversation Memory Agent


4. QUERY UNDERSTANDING AGENT

The Query Understanding Agent analyzes the user's question before retrieval.

It classifies questions into four main categories:

- Factual
- Procedural
- Comparative
- Ambiguous

A factual question asks for a specific piece of information.

A procedural question asks how to perform an action or process.

A comparative question asks for differences or similarities between two or more things.

An ambiguous question does not contain enough information to determine the user's intended meaning.


5. RETRIEVAL AGENT

The Retrieval Agent searches the indexed knowledge base for information relevant to the user's query.

The standard Lumina test configuration retrieves up to 5 relevant chunks.

Each retrieved chunk can contain the following metadata:

- Document name
- Document ID
- Chunk ID
- Section
- Page number
- Relevance score

The retrieval process should prioritize information that is semantically related to the user's question.

If no sufficiently relevant information is found, the system should not use an unrelated chunk as evidence.


6. RESPONSE GENERATION AGENT

The Response Generation Agent creates the final answer using the retrieved information.

The generated answer should remain grounded in the retrieved content.

The system should not invent facts that are not supported by the retrieved information.

When source information is available, the response should identify the document or source used to generate the answer.


7. CLARIFICATION AGENT

The Clarification Agent handles questions that are unclear or incomplete.

For example:

"Tell me about it."

This question is ambiguous because the system does not know what "it" refers to.

The system should ask the user for clarification rather than selecting a random topic.

After the user provides clarification, the original question and clarification should be combined into a refined query.


8. CONVERSATION MEMORY AGENT

The Conversation Memory Agent maintains relevant information from previous turns in a conversation.

For example:

User: What is the Retrieval Agent?

User: What does it do?

The second question should be interpreted using the context of the first question.

Conversation memory should contain relevant previous queries, responses, referenced documents, entities, and topics.

Irrelevant conversation history should not be unnecessarily included in a new query.

10. EXPECTED RAG BEHAVIOR

When a user asks a question whose answer exists in this document, Lumina should retrieve the relevant chunk and generate an answer based on that information.

When a user asks for information that does not exist in this document, Lumina should not pretend that the information exists in the document.

For example, this document does not specify the name of the person who created Lumina AI.

Therefore, if a user asks:

"Who created Lumina AI?"

the system should state that this information is not available in the uploaded document.

The system should not invent a person's name.
